# FunctionOpen 当前计划

## 当前目标

完成现有服务器权威 FunctionOpen、统一初始化和角色升级闭环的真实环境验证，并补齐自动化测试、缓存补偿和业务系统接入。稳定设计与当前能力见 `DESIGN.md`。

## 待完成

- [ ] 在真实 MySQL、Redis、Gateway、Game Server 和 WebSocket 环境验证“登录初始化 → 1级升级 → 开启 FunctionOpen 1001 → 增量推送 → 进入战斗”。
- [ ] 增加 game-server 协议处理单测/集成测试，覆盖重复升级、重复开启事件、重复登录和断线重连初始化。
- [ ] 模拟 Redis 更新失败，验证 MySQL 结果保留、缓存回源重建、恢复后的重试/补偿以及重复补偿幂等。
- [ ] 在真实多人登录环境验证统一初始化消息大小、数据库查询并发、section 错误隔离和 Redis 回源。
- [ ] 将角色、Wallet 和 Bag Repository 接入正式领域 Service，补充操作原因、权限、背包容量、升级规则、体力恢复和审计日志。
- [ ] 验证同一功能的多个入口可以分别采用隐藏或置灰，未开启入口无法绕过检查进入玩法。
- [ ] 后续确有需求时再评估多个 Condition 的 AND/OR 组合及嵌套条件组，不作为当前闭环阻塞项。

## 验收条件

- 服务器事件只在 MySQL 事务成功后产生开启状态；Redis 失败不覆盖数据库结果并可恢复。
- 重复事件、重复升级、重复登录、重复推送和重复补偿均幂等。
- 登录和重连后客户端以统一初始化快照恢复权威状态，运行时增量推送正确更新入口。
- player、wallet、bag 和 functionOpen section 在单个 provider 失败时相互隔离，初始化大小超过预算时明确失败。
- 至少一个真实 UI 入口完成关闭、开启、重连恢复和进入玩法的 LayaAir IDE 验证。
