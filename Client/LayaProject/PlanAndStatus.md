# 当前开发计划

## 当前目标

以现有可运行战斗为起点，先完成可靠的战斗进入、结算和退出生命周期，再依次补齐战斗数据、表现反馈、奖励背包、制作工具和通用外围系统。所有工作按可独立编译、可回退、可在 LayaAir IDE 或目标环境验收的批次推进。

根计划只维护跨模块顺序和总体验收；Scene、SceneObj、FunctionOpen 与 Guide 的专项细节分别见各自目录中的 `PlanAndStatus.md`。

## 实施顺序

### 第一阶段：战斗 UI 与生命周期基础

- [ ] 在 LayaAir IDE 验证已完成的胜利、失败结算页：胜利暖象牙色、失败青蓝色运行时遮罩，标题/信息面板/按钮层级、战斗 HUD 弱场景线索和输入拦截均符合预期；同时验证队伍消灭或 `reportBattleResult()` 只触发一次 `Victory`/`Defeat`，确认后进入 `Exiting` 并串行返回征战界面。
- [ ] 后续在可控延迟环境验证进入战斗 Loading 的 15 秒超时回退征战场景；首包与战斗已确认复用同一 `LoadingMgr`，地图/战斗资源/HUD 就绪关闭和重复进入无残留已通过 LayaAir IDE 验证。
- [ ] 战斗结束时只结算一次，并根据结果显示胜利或失败界面；结果界面确认后由 `SceneMgr` 串行退出并返回征战界面或约定场景。
- [ ] 验证胜利、失败、主动退出、加载失败、暂停、倍速、连续点击和重复进入；事件、Timer、对象池、空间索引、资源引用与 UI 回调均无残留。
- [ ] 在 LayaAir IDE 验证 `MainScene → BattleStageScene → BattleScene` 下顶部、底栏、左右活动栏和底栏选中态；从征战界面切换背包、主世界、商店和设置后，返回主界面时选中态与点击项一致。

### 第二阶段：战斗数据与计算基础

- [ ] 确认生物、子弹和技能配置字段是否沿用旧工程定义，删除只为临时演示存在的字段或默认值。
- [ ] 固化第一版伤害公式，明确基础伤害、攻击属性、倍率、暴击、防御、减伤、治疗和 Buff 修正的计算顺序、取整规则与边界。
- [ ] 定义怪物基础属性、成长或关卡修正、技能组合和初始配置；建立可重复的固定战斗样例用于数值回归。
- [ ] 明确服务器权威数据与客户端战斗模拟数据的边界；客户端显示和表现不得产生独立于战斗结果的第二套数值。
- [ ] 用固定配置回归普通攻击、直接伤害、子弹命中、治疗和 Buff，覆盖暂停、倍速与延迟触发。

### 后续服务端奖励完善

- [ ] 为普通物品奖励补齐服务端背包容量、堆叠和增量同步契约；当前第一批配置仅发放货币，普通物品写库后的 UI 同步尚未开放。
- [ ] 在断线重连、Redis 更新失败与 MySQL 回源环境验证钱包快照与已完成战斗会话的一致性。
- [ ] 在发布前把客户端胜负上报替换为服务端战斗演算或可验证战报；当前会话机制保证归属、配置和幂等，不构成防作弊结算。

### 第三阶段：战斗表现与 SceneObj 生命周期

- [ ] 接入伤害与治疗跳字，保证同一结果只生成一次表现，并在目标死亡、回池或销毁后安全清理。
- [ ] 接入子弹特效、受击特效、恢复 Buff 及对应特效；统一特效时间基准、挂点、层级、对象池和释放方式。
- [ ] 完成 HUD、Buff、Skill、Bullet、Camera follow 和 AI 调度的实体 ID 迁移验证，不允许跨帧保存可回池实体引用。
- [ ] 在战斗入口可重复进入后补齐示例对象注册与创建验证，并验证三组 `AIScheduler` 的选敌、移动、技能 CD、死亡和回池清理。
- [ ] 验证 Camera2D 拖拽、跟随、地图边界、输入归属和场景切换。
- [ ] 确认 Spine 的 ResourceMgr 适配方式；图片和标准 atlas 帧动画继续分别使用 `ResImage` 与 `ResFrameAnimation`。
- [ ] 完成本阶段后执行一次完整战斗回归：加载、战斗、伤害/治疗表现、胜负、退出和再次进入。

### 第四阶段：征战节点、奖励与背包闭环

- [ ] 将征战地图关卡节点改为可复用 `BattleStageNode.lh` 与 Runtime Controller，由 `BattleStage.json` 驱动节点类型、世界坐标、开放条件和战斗路由。
- [ ] 完成普通、Boss、未开放和已通关节点的显示、点击与路由验证，修正剩余节点坐标和资源运行时路径。
- [ ] 在真实场景验证征战底图的竖向拖拽边界、第一关点击和 TiledMap 加载。
- [ ] 在第一版通关奖励闭环的基础上，设计服务器权威的奖励协议和幂等结算服务；失败和主动退出不得错误发奖，重复请求不得重复获得奖励。
- [ ] 为角色升级经验上限提供正式配置，并为顶部 HUD 的水晶位接入对应 Currency Item。
- [ ] 验证结算后即时显示、退出重进、断线重连、Redis 更新失败与 MySQL 回源时的数据一致性。

### 第五阶段：战斗预览、测试界面与技能编辑器

- [ ] 明确工具只在开发/测试环境可用，确定配置来源、保存位置、版本兼容和错误回退边界。
- [ ] 先实现只读战斗预览/测试入口：选择角色、怪物、技能、地图和时间倍率，运行后观察伤害、Buff、子弹、特效和结果。
- [ ] 建立可重复测试用例与结果摘要，支持快速重开并验证场景和对象池无残留。
- [ ] 在只读预览稳定后实现技能编辑器，支持合法字段编辑、校验、保存和重新加载；不得直接修改编辑器生成文件或伪造资源 `.meta`。

### 第六阶段：音乐、音效与设置

- [ ] 建立音乐和音效的统一播放入口，支持场景音乐切换、按钮音效、战斗技能/受击音效及重复播放策略。
- [ ] 实现简单设置界面，至少包含音乐音量、音效音量和静音；配置需本地持久化并在启动后恢复。
- [ ] 验证场景切换、进出后台、暂停、重复进入和资源释放时无叠播、残留或音量失效。

### 第七阶段：GM 指令系统

- [ ] 明确 GM 指令的环境和权限边界；第一版仅开发/测试环境开放，正式环境默认禁用。
- [ ] 建立稳定的指令注册、参数解析、权限校验、错误反馈和审计日志机制。
- [ ] 首批指令覆盖战斗重开、胜负触发、角色/怪物属性调整、物品和货币发放、功能开启及 Guide 状态查询。
- [ ] 所有数据修改继续走正式业务服务，不允许 GM 绕过容量、非负数、幂等和持久化约束。

### 第八阶段：双端与遗留专项验证

- [ ] 在真实 MySQL、Redis、Gateway 和 WebSocket 环境完成登录、升级、FunctionOpen `1001`、进入战斗、结算和返回主城的完整闭环。
- [ ] 补齐 FunctionOpen 的重复升级、重复事件、断线重连初始化、Redis 写入失败补偿和多人登录压力验证。
- [ ] 完成 Guide 的服务器日志链路、LayaAir IDE 双端流程、三种断线时点恢复和 MySQL 幂等集成测试。
- [ ] 增加稳定 `guideKey` 的 UI 目标注册机制，再实现遮罩挖孔、手指提示和只允许目标点击的引导动作。
- [ ] 在可触发真实页面/应用后台状态的浏览器或目标设备验证 Scene 后台恢复：Realtime 补入后台时间，FixedTick 忽略后台时间并从原 tick 恢复。
- [ ] 在 LayaAir IDE 发布产物中确认 `assets/testAndSample/editorResources/` 是否被自动排除。

### 第九阶段：性能基线与专项优化

- [ ] 在普通实现上记录 100/200/400 角色分档基线：FPS、单帧耗时、CPU 主线程、JS 堆、总进程内存、GPU 纹理内存、RenderNode/Node、DrawCall/InstanceDrawCall、纹理切换、逐帧分配和 GC 停顿。
- [ ] 以 iOS 微信小游戏稳定 30 FPS 为目标进行真机压测；30 FPS 对应 33.3 ms，必须为真实玩法保留余量。
- [ ] 只有基线证明现有方案不足时，才评估集中渲染队列、可复用数组/TypedArray、2D Mesh、自定义 Shader 与 GPU instancing。
- [ ] 原型需验证队伍染色、帧 UV 更新、atlas/shader/mask/渲染层排序和真实 iOS 渲染后端，并始终保留非 instancing fallback。

## 当前阻塞与外部依赖

- Scene 后台恢复需要能触发真实可见性切换的浏览器或目标设备，LayaAir IDE 预览不能完成该项。
- UI、血条、子弹、受击、Buff、Loading 和结果界面若缺少正式资源，需要先导入资源并由 LayaAir IDE 生成真实 `.meta` 和 UUID 后再集成。
- FunctionOpen、Guide、奖励和背包的完整验证依赖真实 MySQL、Redis、Gateway、Game Server 与 WebSocket 环境。
- 100/200/400 性能结论和 GPU instancing 决策依赖 iOS 微信小游戏真机数据。

## 总体验收

- 战斗可连续执行“进入、Loading、战斗、胜利/失败、结算、退出、再次进入”，不存在重复结算、重复 UI 响应或生命周期残留。
- 伤害、治疗、血条、跳字、子弹、受击和 Buff 表现来自同一份战斗结果，并在暂停、倍速、死亡、回池和切场后保持一致。
- 奖励、Wallet 和 Bag 在重复请求、断线重连及缓存失败时保持幂等和数据库权威。
- 战斗预览、技能编辑器和 GM 工具仅在允许环境运行，不绕过正式配置、权限和持久化边界。
- TypeScript、文本格式和文档系统检查通过；涉及 UI、资源和生命周期的任务必须完成 LayaAir IDE 或目标设备实测。
