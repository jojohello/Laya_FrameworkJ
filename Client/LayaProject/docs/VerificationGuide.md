# 资源管理器验证方案

我们已更新测试脚本，增加了针对以下三点的验证功能：

## 1. 验证“单个删除资源”

**操作步骤**：
1. 按 **[A]** 键多次（例如 3 次），创建 3 张图片。
   - 控制台显示：`✅ 图片创建成功 (总数: 3)`
2. 按 **[D]** 键一次。

**预期结果**：
- 屏幕上减少一张图片。
- 控制台显示：`🗑️ 删除一个图片 (剩余: 2)`
- 引用计数减少 1（例如从 3 变 2）。
- 对象池缓存增加 1（例如从 0 变 1）。

**结论**：
实现了对单个资源的精确回收。

---

## 2. 验证“优先从 Cache 中取得资源”

**操作步骤**：
1. 确保已执行刚才的删除操作（此时对象池中应有缓存）。
   - 状态：对象池数 > 0
2. 按 **[R]** 键（重新创建图片）。

**预期结果**：
- 控制台必须显示：`[ResourceMgr] ♻️ 从对象池获取: ...`
- 屏幕上增加一张图片。
- 对象池缓存减少 1。
- 不会触发新的网络加载（因为重用了对象）。

**结论**：
证明系统优先复用了对象池中的资源，而非重新创建。

---

## 3. 验证“引用计数为 0 后自动释放”

**操作步骤**：
1. 按 **[G]** 键（启动自动释放测试）。

**程序行为**：
1. **自动清空**所有图片（引用计数变为 0）。
2. **设置缓存时间**为 3000ms（3秒）。
3. **开始倒计时监控**，每秒打印一次状态。

**预期结果**：
- **0~3秒内**：控制台显示 `引用: 0, 缓存: N`（资源还在池中待命）。
- **3秒后**：控制台显示 `================ ✅ 测试通过：资源已被自动释放 ===============`。
- 此时 `refInfo` 为空，说明资源已从内存中彻底清除。

**结论**：
证明 ResourceMgr 能够正确监控引用计数和时间，在超时后自动清理内存。
