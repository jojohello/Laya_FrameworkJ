# 战斗结果界面设计约束

本文件作用于 `assets/ui/battlescene/`，继承项目根目录 `DESIGN.md`。胜利、失败等战斗结果页面以 `750x1334` 为设计画布。

完整界面的设计、资源拆分、目录、拼装和验收统一遵循项目根目录 `DESIGN.md` 的“独立 UI 设计与美术拼装流程”。本文件只补充战斗结果页面特有的尺寸和视觉约束。

## 正式资源尺寸

资源像素尺寸应接近运行时逻辑尺寸，不保留只为生成器输出存在的超大图片。

| 元素 | 建议逻辑尺寸 | 画布占用约束 |
| --- | --- | --- |
| 结果主视觉 | `330x253` 至 `380x300` | 宽度不超过画布约 51%，高度不超过约 30% |
| 标题牌 | 约 `460x180` | 宽度约 61%，装饰不得挤压文字安全区 |
| 结果信息面板 | 约 `560x250` 至 `560x330` | 宽度约 75%，保留左右安全边距 |
| 信息行 | 约 `500x72` | 图标与文字区保持固定节奏 |
| 主按钮 | 约 `260x92` | 不因源图过大而缩成模糊小图 |
| 全屏遮罩 | `750x1334` 的根级 `bg:GImage` 半透明遮罩 | 覆盖画布并拦截输入，不使用整屏结果美术背景 |

九宫格资源另按其固定边距生产；不适合九宫格的角色、徽章和完整插画不得强行配置 `sizeGrid`。

## 战斗结果特有视觉约束

- 结果页保留战斗场景作为底面，并按结果建立轻量情绪区分：胜利使用半透明暖象牙色 `bg:GImage` 建立明亮、轻盈的结算气氛；失败使用较暗的低饱和青蓝 `bg:GImage` 收敛场景。两者都只保留战场轮廓；胜利以暖底衬托蓝晶主视觉与金色标题条和按钮，失败以冷底衬托失败角色与红色标题。战斗 HUD 可保留为战斗结束的弱场景线索，不得争夺结算主体。标题、信息面板、奖励或提升信息和主按钮必须保持清晰轮廓。
- 胜利和失败共享公共标题条、九宫格信息面板与主按钮，差异只由主视觉和结果文字表达；不得为任一结果页增加 Loading 式整屏背景。
- 胜利与失败可以使用不同的角色表情、徽章和装饰主题，但边框重量、材质、色温、按钮尺度和文字层级必须属于同一套项目视觉语言。
- 胜利、失败的信息结构和后续动作不同，继续使用独立 `.ls` 与 Controller；真正复用的物品格等结构使用公共 `.lh`。
- 失败建议是可变数量的同构信息行，使用可拖拽的纵向 `GList`；胜利奖励是可变数量的物品格，使用可拖拽的横向 `GList` 并复用 `ItemView.lh`。列表必须在 `.ls/.lh` 中声明 `clipping` 和与布局同方向的 `Scroller`：`Touch Effect=On`、`Bounceback Effect=On`、`Bar Display=Hidden`；固定滚动组件禁止由 Controller 临时创建。数据排版后调用 `layout.refresh()` 使内容尺寸和滚动重叠区重算，超出可视区域时可拖拽查看且每次打开回到起始位置。不要把 `Scroller.setViewSize()` 当作刷新 API，它会改变 List 自身尺寸；无点击语义的条目不得截获拖拽。
- 结算类信息面板默认使用 2 到 3 层底板区分区域：全屏遮罩背景由根节点同级的 `bg:GImage` 在 `.ls` 明确声明，暖色九宫外框叠在其上，较浅的分区标题底板承载标题，低对比内容内嵌面承载列表或奖励。胜利和失败的 `bg` 保持相同尺寸、根节点关系和输入拦截方式，但颜色服务于结果语义：胜利使用 `surface-bg-cream.png`、`alpha=0.84`；失败使用 `surface-bg-blue.png`、`alpha=0.88`。不得再增加同职责的全屏或窗口底色、`modalMask` 节点或 Controller 绘制代码。纯色底板统一使用公共纯色九宫资源，并在 `.ls/.lh` 直接配置 `GImage`、尺寸与透明度，禁止由 Controller 临时绘制。任何承担可见图片、色块、边框或底板职责的节点必须是 `GImage`；`GBox` 只能用于无视觉的布局容器或结构分组。内层应更轻、更平、更低对比，不能用另一张大而厚重的主面板替代。主视觉、标题、遮罩和确认操作属于固定页面骨架，不得为形式强行列表化。
- 结果页的根级背景使用宽高 Relation 覆盖画布；主视觉、标题、评分、信息区和主按钮使用根节点 `Center_Center + Middle_Middle` Relation，随画布比例变化整体居中平移，禁止拉伸固定尺寸的插画、文字或按钮。各信息区的内部节点保持相对父容器定位，避免层层重复绑定根节点。

## 已确认的错误与防范

- 使用暗黑写实失败门作为大面积主视觉，导致与明亮 Q 版西方魔法风格冲突；结果主视觉应先验证角色气质、轮廓和目标显示尺寸。
- 把失败门或其他单个插画放得过大，会让结果页变成海报并挤压标题与信息区；主视觉必须遵守本页尺寸表和占用比例。
