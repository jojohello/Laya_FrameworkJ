# AI 文档接入协议

本文件只规定智能体如何读取和维护项目文档，不承载具体模块设计。项目事实以对应作用域内的 `README.md`、`DESIGN.md` 和 `PlanAndStatus.md` 为准。

## 开始任务

1. 确定本次改动的最小目录作用域。
2. 从仓库根目录开始，按父目录到目标目录的顺序读取沿途存在的 `DESIGN.md`。外层规则自动作用于子目录。
3. 读取目标目录及必要父目录的 `README.md`，确认已有能力、公开入口和使用方式。
4. 只有在任务涉及未完成工作、优先级或交接时，才读取相关 `PlanAndStatus.md`。
5. 文档不存在是合法状态，不要为了补齐形式创建空文档。

不要假设编辑器会自动加载模块文档；需要的信息必须主动读取。不要依赖某个智能体的私有记忆代替仓库文档。

## 三类文档

| 文件 | 回答的问题 | 允许内容 |
|------|------------|----------|
| `README.md` | 这是什么、现在能做什么、怎样使用 | 当前能力、公开 API、目录索引、使用示例 |
| `DESIGN.md` | 为什么这样设计、在此作用域内必须怎样实现 | 架构边界、稳定约束、设计取舍、反复出现错误的防范规则 |
| `PlanAndStatus.md` | 现在还要做什么 | 未完成任务、当前优先级、阻塞、验收条件 |

详细边界和继承规则见 [DESIGN.md](DESIGN.md)。

## 更新规则

- 行为或公开入口变化：更新最接近该能力的 `README.md`。
- 稳定设计或约束变化：更新最小有效作用域的 `DESIGN.md`。
- 当前任务、顺序、阻塞变化：更新相应 `PlanAndStatus.md`。
- 任务完成后，不在 Plan 中保留过程历史。先把仍有长期价值的结果提炼到 README 或 DESIGN，再删除完成项；Plan 没有未完成内容时可直接删除。
- 智能体已获授权删除完成后的 Plan 文件，但删除前必须确认其中没有唯一的当前信息。
- 内层规则可以补充外层规则。需要违反外层规则时，必须在内层 `DESIGN.md` 明确声明例外、影响和原因，并得到用户确认后执行。
- 新规则应来自实际需求、重复错误或已经确认的设计决策。不要预先堆积尚未发生的规则；失效规则应及时删除或修订。

## 实施与验证

- 先查看实际代码和配置，再修改文档；文档不得替代源码核对。
- `src/logic/*` 和 `src/start/*` 下通常一个一级目录就是一个完整模块，按 [DESIGN.md](DESIGN.md) 的模块边界执行。
- TypeScript 静态检查：`npx.cmd tsc -p tsconfig.json --noEmit --pretty false`
- 文本格式检查：`powershell -ExecutionPolicy Bypass -File tools/docs/validate-text-format.ps1`
- 文档系统检查：`powershell -ExecutionPolicy Bypass -File tools/docs/validate-doc-system.ps1`
- 运行、预览和发布通过 LayaAir IDE 3.3 完成；不要假设本目录存在 `npm run dev` 或 `npm run build`。

## 契约型代码注释

- 当代码正确性依赖非显然的更新顺序、状态所有权、数值边界或容差、生命周期清理、回池复用、兼容性取舍时，必须在最容易被误改的执行边界旁添加简洁的契约型注释。
- 契约型注释说明“为什么这样实现”“必须保持什么约束”以及“破坏约束会产生什么风险”，不得只复述语句、循环、赋值或已经由命名和类型清楚表达的机械行为。
- 修改相关实现时必须同步核对并更新注释；失效注释不得保留。若约束跨越多个模块或具有长期架构价值，还必须写入最近有效作用域的 `DESIGN.md`，源码旁仍保留防止局部误改所需的最小注释。
